## Features

- New sandbox containers mount your vault read-write at `/vault`, independently of the working directory at `/work`. Guest code can modify or delete notes; the VM is not a vault-protection boundary. (#688)
- VM-routed interactive Claude threads can request a host command through `host_exec`. Each command requires a fresh Allow once / Deny decision, regardless of permission mode; scheduled threads cannot use it. (#689)

## Bug fixes

- Returning to an older Claude thread no longer gets stuck on a missing native conversation. Before assistant or tool work starts, Agent Threads retries once with recent saved context and the pending message, preserving images and preventing duplicate or stale message replays. Existing harness containers and their native history are preserved through routine mount changes and stop/restart. (#691)

## Improvements

- Container-routed Claude sessions no longer advertise unusable `enter_vm` and `exit_vm` tools. `vm_exec` remains available, and host-local/fallback sessions retain their lifecycle tools. (#690)

## Notes

- Existing harness containers keep their actual mount set; newly configured mount paths are available in new containers. Explicitly removing a container deletes its guest-native history.
- Recovery supplies bounded recent context, not the full deleted native transcript.
- Update through Settings → BRAT → Update all beta plugins.
